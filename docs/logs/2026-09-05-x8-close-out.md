## What didn't go as planned, and why

### 1. Slice 4b was retired rather than shipped

The wave was planned with a 13th `M3LHumanActionKind` and a `CHECK`-widening
migration behind it, on the reasoning that slice 4a added a view endpoint and
ADR-0070 audits views. Re-derivation at implementation time found the premise
inverted: `boot/human-action-specs.ts` had already decided that `view.*`
covers sensitive-class renderings only, every unaudited `/api/v1` path is a
GET list or detail, and ADR-0070 puts telemetry on the persist side of its own
display-vs-persist rule. What shipped instead is a test pinning the audited-GET
spec keys to exactly three.

**Why it happened:** The slicing document reasoned from ADR-0070's summary
sentence rather than from the spec table the code actually consults. The two
disagreed, and only the code was load-bearing.

**Fix for future:** When a slice's scope is a vocabulary widening, grep an
existing member of that vocabulary before budgeting the work — the call sites
say whether the new member belongs, and a plan's census does not.

### 2. The plan named the wrong constraint for the extraction

Slice 5a-ii's plan made the cleanup-dispatch extraction conditional on
eslint's `max-lines-per-function`, measuring `runCleanup` at 55 effective
lines against 60. The binding limit was a different rule:
`buildDriverFailureContext` sat at cyclomatic complexity exactly 10 against
`complexity: ["error", 10]`, and a fourth driver would have taken it to 13.
The extraction landed as its own `refactor:` commit before any feature work.

**Why it happened:** The plan measured the one budget it had been burned by
before and did not enumerate the other eslint rules the file was subject to.

**Fix for future:** A file near any budget is usually near several. Read the
eslint config's rule block for the zone, not just the rule that last failed.

### 3. `stat` follows symlinks, and the inventory was an audit surface

`listSegments()` first used `stat`. A probe against the built output — one
real 5-byte segment plus a symlink to a 35-byte file outside the tree, a
directory, and a FIFO, all at segment-shaped names — reported 4 segments and
`totalBytes = 4136`. Two faults at once: the number an operator judges the
trail's footprint by became attacker-influenced, and the size and mtime of a
file outside the stream directory leaked through an audit surface. Fixed with
`lstat` plus a regular-file check, and the planted entry raised into a
`skipped` count rather than dropped.

**Why it happened:** The writer and `read()` both refuse planted links with
`O_NOFOLLOW`. The inventory was the third path onto the same directory and
was written against the reader's shape without inheriting its threat model —
because it opens nothing, and the refusal lived in the open flags.

**Fix for future:** When adding a third path onto a directory two others
already guard, enumerate what those two refuse and check each refusal
survives the new access pattern. A guard expressed in `open` flags does not
transfer to a path that never opens.

### 4. My own hardlink claim was false, and the leak it excused was live

Having fixed the symlink case, I wrote — into the code comment, `storage.md`
twice, and ADR-0070 — that a hardlink at a segment name is "indistinguishable
by any `stat`/`lstat`", and documented it as an accepted limit. The re-review
executed `lstat` against a planted hardlink and got `nlink = 2, size = 987654`.
I reproduced it. The claim was wrong and the disclosure was real. Added
`stats.nlink === 1`, deleted the claim in all four places, and replaced it
with the two limits that are true: an inventory cannot tell which link is the
one it created, and the check is path-based so it is not TOCTOU-free.

**Why it happened:** I reasoned about `lstat` from what it is for (not
following the link) rather than from what it returns, and then wrote the
conclusion into four files where it read as verified.

**Fix for future:** A stated security limit is a claim, and an accepted-limit
sentence is the most expensive place to be wrong — it tells the next reader
not to look. Execute the probe that would disprove it before writing it down.

### 5. A surviving mutation was an environment coincidence, not a missing assertion

Removing the `(datePrefix, sequence)` sort killed no test. The fixture was a
deliberately "scrambled" directory, so the obvious reading was a missing
assertion. It was not: ext4's `dir_index` returns names in hash order, which
for zero-padded segment names coincides with sorted order, so the fixture
could not scramble anything regardless of creation order. Verified in a
scratch directory. Fixed with a dedicated file mocking `readdir` alone and
leaving `stat` real; re-mutation killed it.

**Why it happened:** The fixture encoded an assumption about the filesystem —
that creation order determines `readdir` order — which is not part of any
contract and happened to be false here.

**Fix for future:** When a mutation survives a fixture built to defeat it,
suspect the environment before the assertion. A fixture whose property comes
from the filesystem rather than from the test can pass on one machine and go
vacuous on another silently — mock the boundary instead.

### 6. Two expectations derived from the call under test

In both `audit-trail-usage.test.ts` and later `cleanup.test.ts`, the expected
values were computed from `stream.listSegments()` — the very call being
asserted. Both were rewritten to derive independently from `readdir` plus
`stat`.

**Why it happened:** The expected value was genuinely awkward to state by
hand (a byte total over a temp directory), and the call under test was the
convenient way to get it.

**Fix for future:** `.claude/rules/tests.md` already carries this rule. The
signal it needs a second look is a temp-directory fixture whose expected
value is a computed aggregate — that is where the shortcut is tempting.

### 7. The version bump ADR-0070 recorded as shipped had never landed

ADR-0070's X7b Update and the X7b tracker row both record `m3l-common`
4.6.1 → 4.7.0 for the three optional correlation fields. `git log` on
`packages/m3l-common/package.json` showed the last non-dependency commit set
4.6.1. The code had landed; the bump had not. Recorded as a correcting
subsection in the new Update rather than fixed silently, and 4.7.0 now carries
X7b's fields as well as `listSegments()`.

**Why it happened:** The bump was named in an ADR Update and a tracker cell,
neither of which any gate compares against `package.json`.

**Fix for future:** A version claim in prose is unverified by construction.
When an ADR Update says a bump shipped, check `package.json`'s history before
building on it.

### 8. A spoke reported a false claim about library behaviour

A spoke reported that `2026-01-01-00005.jsonl` would be counted, because the
segment-name pattern admits `\d{4,}`. Executing against `dist/` showed it is
rejected: the parser re-renders the parsed sequence with `padStart(4, "0")`
and declines the name unless it round-trips. The regex is only half the
parser. Dispatched a correction and restored the case to the fixture.

**Why it happened:** The spoke read the pattern constant and stopped there.

**Fix for future:** Do not accept a spoke's claim about a parser from the
pattern alone; run the parser. This is the second incident in the wave where
executing beat reading. _(promoted → .claude/rules/subagent-dispatch.md)_

### 9. A spoke ran bare `git stash` against a shared stash stack

While diagnosing an unrelated `pnpm lint` OOM, a spoke ran `git stash`
followed by `git stash pop`, unprompted. `git stash list` afterwards showed
`stash@{0}: WIP on feat/hub-single-view` — a different session's entry, still
intact. The pop took the spoke's own entry only because it happened to be on
top. Nothing was lost, and only by ordering.

**Why it happened:** The stash stack is shared across every worktree of a
repository, and nothing in the spoke prompts said so. `git stash` reads as a
local, reversible convenience.

**Fix for future:** Forbid `git stash`, `git stash pop`, and `git checkout --`
in the writer-spoke prompts outright. A spoke never needs to set work aside;
that is the hub's decision.

## Lessons learned

- **A guard in `open` flags does not transfer to a path that never opens** —
  the writer and `read()` refused planted links via `O_NOFOLLOW`; the
  inventory inherited the shape and not the refusal. When adding an access
  path to a directory others guard, enumerate each existing refusal and check
  it survives the new pattern.

- **Execute the probe that would disprove a security limit before writing it
  down** — an "indistinguishable by any `stat`" sentence tells the next reader
  not to look, so it is the most expensive kind of wrong. `lstat` returns
  `nlink`; that is exactly how the fix works.

- **A surviving mutation can be an environment coincidence** — an ext4
  `dir_index` ordering made a "scrambled directory" fixture unable to
  scramble. When a fixture built to defeat a mutation fails to, suspect the
  filesystem before the assertion, and mock the boundary so the property comes
  from the test rather than the machine.

- **A file near one budget is usually near several** — `max-lines-per-function`
  was the budget the plan measured; `complexity: 10` was the one that bound.
  Read the zone's whole eslint rule block before sizing an edit.

- **A version claim in prose is unverified by construction** — no gate
  compares an ADR Update or a tracker cell against `package.json`. Two
  documents agreed a bump had shipped and it had not.

- **Grep a member, never trust a plan's vocabulary census** — slice 4b was
  budgeted from an ADR summary sentence and retired once the spec table the
  code consults was read. The call sites decide whether a new member belongs.

- **Spokes must never `git stash`** — the stash stack is shared across every
  worktree of the repository, so a spoke's convenience can pop a concurrent
  session's work while `git diff` reports a clean tree.
  _(promoted → .claude/agents/code-implementer.md, .claude/agents/test-author.md)_

- **Re-derivation at implementation time is the wave's most productive step**
  — it retired one slice outright, inverted another, and corrected a recorded
  version. In each case a document authored days earlier disagreed with the
  code, and only the code was load-bearing. Budget for the check rather than
  treating a plan's census as settled.
